{% comment %} Polled while a draft is being generated. Rendered as a fixed overlay rather than inline in the form: generation takes up to a minute and the creator must not miss that it started, nor keep editing a form whose values are already on their way to the model. Inline it also sat below the fold on a laptop, which is exactly the confusion this replaces. The card is spinner + title with a live elapsed counter + rotating quips — the shape settled by mockup with the user on 2026-08-17 (see openspec/changes/generation-wait-quips-return/overlay.mockup.html), modelled on Claude Code's own status line: personality plus a ticking fact, no progress bar. The bar was tried and removed the same day: an indeterminate sweep irritates, and a determinate fill needs streamed counts production no longer has. Elapsed wall-clock is the one number a wait screen can show without measuring the backend. The no-fabricated-stages rule is unchanged: quips are entertainment, never telemetry, and must not imply a pipeline stage the backend does not have. When streaming DOES supply real counts (PR previews), the out-of-band fragment fills #gen-progress with the drafted-counts caption — data beside flavour, neither displacing the other. {% endcomment %}
{% comment %} The poller is a separate, empty element with hx-swap="none": while the draft is pending the endpoint answers 204 and nothing in the DOM changes. Polling the overlay itself (and swapping it whole every 2s) restarted its animations on every tick, which read as the screen flickering. {% endcomment %}
