{% comment %} Swapped into the waiting card when the draft has actually grown. Out-of-band on purpose: the poller keeps hx-swap="none", so this element is the only thing that changes and the card's spinner and fade-in are untouched by a poll. The data attributes are what the poller sends back next tick, which is how the endpoint can answer 204 when nothing has moved. The bar's fill is computed server-side (see EXPECTED_QUESTIONS in editor_views.py) from questions the model has finished writing, and is capped below full: the bar may park near the end, but it can never sit at complete while the draft is still arriving — that is the progress-bar lie this design exists to avoid. The caption states the only exact facts we have; there is deliberately no percentage label, which would claim a precision the calibrated denominator does not possess. {% endcomment %}
