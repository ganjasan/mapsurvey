Budget question — user journey, v1

Один тип вопроса Budget (Split a budget · Choose projects within a budget) + бюджет группы: у обычных гео-вопросов внутри группы появляется цена × два источника позиций (список · объекты слоя на карте). Пример: «How would you spend £20M across Immingham» (prod #1435, сейчас сделан через ranking).

Решения: бюджет = QuestionGroup.budget {total, unit, symbol}; цена = validation_settings['price'] {amount, per ∈ feature | length | area} у гео-вопроса, блок Price показывается в модале вопроса только внутри бюджетной группы. Стоимость отметки = amount × (1 | метры | м²), на сервере через Web Mercator с поправкой cos(lat) как у spray, в браузере distanceTo / geodesicArea. Кнопка «за штуку», которая уже не влезает, гаснет с причиной; линию или площадь, которая дороже остатка, страница не оставляет и пишет, сколько она бы стоила. Сервер принимает отметки группы по порядку, пока хватает бюджета, остальные отбрасывает (как max_features). Нового пути размещения нет.
Результаты (экран 8): блок группы перед её вопросами: по каждому — отметок / метров / м², стоимость, доля расхода; сами отметки — на карте, как у любого гео-вопроса. Экспорт: свойство cost у каждой платной отметки, колонка «‹группа›: spent» у респондента.

Ошибки и крайние случаи

Please allocate the whole £20M — £5.5M is still unallocated.
The projects you picked cost £21.5M, which is over the £20M budget. (серверная проверка — если клиент обойдён или JS выключен)
СлучайПоведение
Вопрос не required, респондент ничего не трогалОтвета нет (как у ranking). Если тронул хоть одну позицию — включаются правила.
required + Split «потратить всё»Next недоступен, подпись говорит сколько осталось; сервер повторяет проверку.
Split «до бюджета», requiredХотя бы одна позиция > 0.
Сумма не кратна шагу (ручной ввод)Округляем к ближайшему шагу на клиенте; сервер отклоняет некратное.
Автор меняет total после ответовСтруктурное изменение → Unpublished changes (старые ответы хранят абсолютные суммы и свой total в Answer; доли считаем от сохранённого total версии).
Автор удаляет позицию с ответамиКак удаление отвеченной опции у choice — структурное, 409 acknowledgement.
Объект слоя без стоимости (Projects по слою)На карте виден, в попапе «No cost set — can't be picked»; в редакторе бейдж «2 objects have no cost».
Слой изменён после публикации (стоимость объекта)Живо для новых респондентов (слои не копируются); ответы хранят ключ объекта + стоимость на момент ответа.
Без JSSplit: числовые поля; Projects: чекбоксы; проверка только серверная.
Бумажная форма (print)Split: таблица «позиция — ____ £»; Projects: чекбоксы со стоимостью и строка «Total». Распознавание в paper-entry — потом.
ПереводыНазвания и описания позиций — через существующие choice-переводы (question:<code>:choice:<code>) + новый ключ для description.
Responses → Overview. Блок вопроса рядом с choice-блоками. Агрегат — один модуль (как object_stats.py для объектов), им же пользуется Public results.

Открытые вопросы к владельцу

ВопросМоё предложение
Pro или free?Free — Split и Projects списком; Pro — источник «объекты слоя» и режим Place items (оба — карта, geobudgeting). Это как раз то, что продаёт картографическому заказчику, а списочный вариант нужен, чтобы precept-консультации вообще делали у нас, а не в Commonplace.
Где хранить ответНовое поле Answer.budget (JSON): {"total": 20000000, "items": {"1": 6000000, …}} для Split; {"total": …, "picked": ["1","3"], "costs": {…}} для Projects; для слоя ключи — ключи объектов. selected_choices не трогаем, чтобы не ломать choice-стек.
Проценты как единицаЭто Split с total=100, символ «%», шаг 5 по умолчанию. Не отдельный режим.
Третий кандидат из #447 — налоговый trade-off (increase/keep/decrease по услугам с эффектом на счёт)Не в этой change; это матричный вопрос с формулой. Отдельный issue после.
Ограничение «не больше X на одну позицию» в SplitОпционально max_per_item, v1 без него, если не попросят.
Place items: цена за штуку одинаковая, или размер объекта влияет (площадка маленькая/большая)?v1 — фиксированная цена за тип; «размеры» = два типа в каталоге.
Нужна ли «полоса остатка» в Split-на-карте на телефоне поверх картыДа, как у панели: липкий верх панели-оверлея.
