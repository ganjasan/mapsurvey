Mockup · agent-onboarding (#312, epic #378)

Three ways to start, and the path through your own AI agent

The third card on /editor/surveys/start/ comes alive now that the MCP server (#306) is up. Who it is for: someone who is not technical and already has Claude or ChatGPT open in another tab. The design rule: never show a token, a URL to type or a config file on the main path. Every client gets its own tile and the simplest instruction it allows: one button where the vendor has an install link (Claude, Cursor, VS Code), one command for terminals, the fewest numbered steps for the rest. An assistant that cannot connect to outside tools at all is told so honestly and offered a way forward, never left without an answer.

Connect Mapsurvey to ChatGPT

About a minute, on a computer. You need a paid ChatGPT plan (Plus, Pro, Business or Enterprise).

  1. Open ChatGPT Plugins and press + → Add custom MCP server.
  2. Paste this address and choose OAuth:
    https://mapsurvey.org/mcp Copy
  3. ChatGPT warns about custom servers — that is normal. Press Create, then Connect.
  4. On the Mapsurvey page that opens, press Allow.
Waiting for ChatGPT to connect… this page updates by itself.
Unverified facts to check before writing the copy: ChatGPT's plan matrix (the OpenAI help article could not be read; third-party sources say there is no custom MCP on Free, and Business has it for admins only), and the exact names on the Plugins screen. The previous "Developer mode" path is what our help page still describes and has to be updated.
A small screenshot per step (from a real ChatGPT account) would help more than words here; to be taken before release.
The real one-click path for ChatGPT is the app directory, not a file: once Mapsurvey is a listed app (Apps SDK, OpenAI verification, review 3–7 business days), this panel shrinks to "Open Mapsurvey in ChatGPT → Connect → Allow", and it works on Free, Go, Plus and Pro, but not in the EEA, Switzerland or the UK. Until then the custom-server steps above apply, and they may need Business/Enterprise for write actions (Pro: read only), which also needs checking. Same for Claude: a listing in Claude's Connectors Directory puts Mapsurvey in the built-in list. Both are separate issues.

Cursor = cursor://anysphere.cursor-deeplink/mcp/install?name=mapsurvey&config=<base64 {"url":…}>; VS Code = vscode:mcp/install?<urlencoded {"name","type":"http","url"}>. Both are only links the browser hands to the app. The OAuth return trip goes to loopback (localhost:8787, 127.0.0.1:33418) or vscode.dev, which the OAuth server already accepts. No cursor:///vscode:// redirect URIs needed.
Out of scope: MCPB bundle (it needs a token and a download, and is not simpler than the Claude link), an MCP Registry entry, Gemini app (US only, Spark). Each can be its own issue.
