Languages: the source column is any language of the survey (default the primary — the one whose text lives in the base fields; “English” here is just this survey), the target any other; both are in the URL and remembered per survey in the browser. “+ Add language…” in the target picker (owner only) opens the Survey-settings picker in place. Rows: status dot · where (the element and, for a repeated text, the usage count that unfolds the list of places) · the source, read-only · the translation. Plain fields are a textarea that autosaves on change; rich fields (Formatted text, section intro, group description, thank-you page) get the same editor the modals use. A group row with one field writes every occurrence; Translate separately splits it. Outdated rows keep the old translation visible and say what the English was. The import report lists unmatched rows by their text — nothing is dropped silently.

5. Where a link lands new deep link

Every element label, every place in a usage list and every page row is a link into the Survey tab:

  • a page → /editor/surveys/<uuid>/?section=<id> — exists today, opens that section;
  • a question or an option → ?section=<id>&question=<id> — new: opens the section and the question's modal, scrolled to its Translations block for that language;
  • the thank-you page → ?panel=thanks — exists today.

The modal is where the full context lives (choices table, help text, preview). The table row is the short way, the modal the long one — a click apart. Browser Back returns to the table at the same row (#row-<key>). In the mockup every link just scrolls here.
