Один механизм подвопросов — две версии

Решение владельца 2026-09-01: п. 0 (редактор) — утверждён. A (попап на карте) — утверждён как default. B (карточка в панели) — не сейчас; позже как альтернативный вид, переключаемый создателем, не замена. Гео-вопрос без подвопросов — норма, нужны подсказки, а не принуждение.

Сегодня «вопрос про объект на карте» существует один раз — подвопросы гео-вопроса: в редакторе «Add Sub-question» под точкой/линией/полигоном, у респондента — Leaflet-попап на поставленной метке с формой и кнопками 🗑 ✎ ✓. Если «Объекты на карте» получат свой механизм (вложенный список в модалке + карточка в панели), создатель будет учить два способа сделать одно и то же. Ниже две версии, где механизм один: A — всё как в гео-попапах; B — всё как карточка в панели, включая старые гео-вопросы. Редактор в обеих версиях одинаковый (см. п. 0) — различие только на стороне респондента.

0 · Редактор — общий для A и B: подвопросы в двух местах, и для гео-вопросов, и для объектов

Наблюдение владельца: многие создатели не ставят подвопросы к точке, а добавляют отдельный вопрос следом. Прод, 2026-09-01 (`geo_subq_usage.sql`): 863 гео-вопроса, подвопросы есть у 57.8% (499); из 364 без подвопросов — 112 (31%) сразу сопровождаются обычным вопросом в той же секции (Dorval Odor «2.1 отметьте точку → 2.2 опишите запах», EMGS Vienna «Places of study → …comments», ITS «титик → пережили ли…»), 137 — ещё одним гео-вопросом, 114 — последние в секции. По опросам с ≥5 сессиями: 296 с гео, 144 используют подвопросы, 53 — только «вопрос следом», 2 — оба паттерна, 37 — ни того ни другого. То есть каждый пятый живой опрос обходит подвопросы вручную. Кнопка «Add Sub-question» под вопросом в списке — вторичная точка входа, которую не находят в момент создания вопроса. Поэтому подвопросы появляются в самой модалке при создании/редактировании любого вопроса с объектами на карте — Geo Point / Line / Polygon и Objects on the map — как вложенный список по паттерну «Choices». Кнопка «Add Sub-question» под вопросом в списке остаётся: оба входа ведут в одну и ту же модалку «New Sub-question for “…”» и в один и тот же `.subquestion-list`.

Гео-вопрос без подвопросов — нормальный случай (решение владельца 2026-09-01): ничего не блокируем и не требуем. Нужны только визуальные подсказки: пустой список «Sub-questions» в модалке с одной строкой «Describe each place with sub-questions — each becomes a column in QGIS» (текст уже есть в geo tips) и «Add sub-question» на расстоянии одного клика; в списке секции — тот же «Add Sub-question» под вопросом. Что делать со старыми опросами, где «вопрос про точку» — отдельный вопрос следом: не мигрировать автоматически (ответы уже собраны в другой структуре); можно подсветить бейджем в списке «looks like a follow-up to the geo question above — make it a sub-question?» с действием «Move under» — это отдельный маленький change.

A · «Как гео-попапы»: список в панели только для поиска, вопросы — в Leaflet-попапе на карте

Клик по строке списка или по объекту на карте → карта подлетает и открывает тот же попап, что на респондентской метке: контент объекта + форма подвопросов + ✓. Ответ сохраняется по ✓ (как сейчас у гео), не по изменению. Кнопок 🗑 ✎ у объектов создателя нет — только ✓.

B · «Карточка в панели для всех»: подвопросы гео-вопросов тоже открываются в панели

Клик по объекту создателя или по своей метке → панель показывает карточку с подвопросами (гео-карточка — с кнопками Удалить / Готово вместо ✓). Ответ на объект создателя сохраняется по изменению; гео-карточка сохраняется по «Готово» (иначе незавершённая геометрия). Попапов на карте нет вообще.

Конфликт со спекой geo-multi-feature-input: «Placed features are managed on the map, not in a panel list» — ранняя сборка показывала строки «Answer 1 / Answer 2» в панели, их убрали как дублирование меток и счётчика. Версия B не возвращает список строк для гео-вопроса (счётчик-чип остаётся единственным индикатором), но переносит попап в панель — это требование «edit/delete through the popup on the map» придётся пересмотреть.
