New survey in the user's order: goal → place → draft

The current page leads with the least meaningful field (name) and buries the two biggest decisions — what to find out and where — at the middle and bottom of a long scroll, with a 320px map fighting the page for touch gestures. Both variants below reorder around the user's decisions and give the map a full screen of its own (which also kills the map-pan-vs-scroll bug and the stray magnifier). Name and languages leave the critical path: A name is suggested automatically, languages live in Survey settings.

GOne breakpoint decides the shape: <1024 = wizard (map always full-screen), ≥1024 = merged two-column. The 768–1023 band never embeds the map into a scrolling form — that is the bug class we are removing, on every width where the two-column doesn't genuinely fit.

Shared decisions (for design.md)

  • Order follows the user's decisions: goal → place → path (AI / empty). Name never appears in the flow (suggested automatically, rename in the editor); languages leave the create flow entirely (Survey settings, sane default).
  • The framing map always gets a full screen — never embedded in a scrolling form on mobile. Kills the pan-vs-scroll conflict and the stray absolute-positioned search icon in one move.
  • Drafting is the default path, "start empty" the explicit alternative — matches real usage (drafting is the used feature) and Mapsurvey's positioning.
  • A = fewer decisions per screen, B = fewer taps. A suits first-time creators (the funnel's weak point); B suits repeat creators. They share the map screen component, so A can even be the first-run experience and B the repeat one later.
  • Desktop ≥1024 keeps the two-column layout (form left, live map right) with blocks reordered to match: goal first, name collapsed.
