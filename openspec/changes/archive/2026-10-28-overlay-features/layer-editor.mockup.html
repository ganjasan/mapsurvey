Редактор объектов — отдельный экран (D9)

Решение владельца 2026-09-01: не таб в карточке слоя, а свой экран по адресу /editor/surveys/<uuid>/layers/<id>/, вход из Survey settings → Reference layers → «Open editor». Три причины: создатель без GeoJSON рисует объекты на карте; создатель без хостинга загружает файлы; слой на сотни объектов требует списка с поиском, фильтрами, клавиатурой и массовыми операциями. Хром — тот же редакторский (topbar, табы, кнопки); раскладка — три колонки: список · карта с инструментами рисования · карточка объекта. Поглощает бэклог FD-17 «draw overlay layer in editor».

Что здесь решено

  • Три входа: рисование, GeoJSON, CSV с координатами. Все дают один и тот же объект с картой и карточкой. GeoJSON — больше не ворота.
  • Ключ объекта генерируется автоматически (`m-034`), из GeoJSON берётся `key_field`, если задан. Это то, к чему привязываются ответы (#152) и экспорт.
  • Масштаб: список виртуализирован, поиск ⌘K, чипы «без фото / без текста», multi-select с массовыми действиями, ↑↓/Enter и Prev/Next по отфильтрованному списку, карта следует за выбором.
  • Массовый контент: CSV (title/category/description/link, матч по key или title) и загрузка папки фото с матчем по имени файла — иначе 214 карточек руками.
  • Вложения — загрузка в публичный S3-tier с лимитом 25 MB на файл; видео большого размера — embed-ссылкой (YouTube/Vimeo, iframe уже в allow-list санитайзера).
  • Layer settings (цвет, label field, popups, per-section visibility) остаются в карточке слоя в Survey settings — экран редактора про объекты, не про слой.
  • Не в этом экране: стилизация отдельных объектов (simplestyle из файла по-прежнему уважается), версионирование слоя, совместное редактирование.
